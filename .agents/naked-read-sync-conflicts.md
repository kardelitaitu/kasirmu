## The finding
`sync::list_sync_conflicts_scoped` is registered and reaches the network with **no permission check at any depth**.

- defined `apps/desktop-client/src/commands/sync.rs:429`, registered `apps/desktop-client/src/lib.rs:1262`
- its entire authorization surface is [sync.rs:434] `state.resolve_scope(&session_token)?;`
- depth 2 `AppState::resolve_scope` [state.rs:598-626] = `resolve_session(token)` + `open_store(...)`
- depth 3 `resolve_session` [state.rs:450-475] = session-store lookup + expiry check + `InvalidSession`
- **permission markers found in all three: none.** Not a macro, not a router, not a bridge shim (`oz_bridge::` never appears in the body), so the `gated_bridge_stems` escape does not apply.
- then it builds an outbound reqwest GET to `{base}/api/sync/conflicts` [:440] and returns `body.conflicts` [:465].

The contrast is in the same file, nine lines away:

- [sync.rs:482] `require_permission_for_session(&state, &session, permissions::SYNC_MANAGE).await?` — the **write** twin, `resolve_sync_conflict_scoped`, asks for `SYNC_MANAGE`.

Authenticate-then-assume on a read whose write neighbour is gated. That is the shape this pin exists to catch.
