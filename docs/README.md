## Conventions

- **ADR naming (new records):** `YYYY-MM-DD-adrNN-<slug>.md` in `decisions/` — the
  `adrNN` segment is required for anything added from here on. Only 13 of the 66 files
  currently in `decisions/` carry it; the other 53 predate the convention and are **not
  drift to be renamed**. Highest number in use: adr47. (Corrected 09-09-26: this read 64/51
  and was already wrong when written — `git ls-tree 04407b60e -- docs/decisions` counts 66
  tracked `.md` files, 13 with the segment.)
- **Spec phases:** `workspace-settings-phase-<N>-<slug>.md` in `specs/`
- **Audit findings:** tracked in [`records/audit-open-findings.md`](./records/audit-open-findings.md)

### The records index is generated, and nothing enforces its freshness

This section used to make one claim. It now has to hold three, and they no longer share a
state: read them apart, because collapsing them into a sentence is how the stale version got
believed for a month. `docs/records/README.md` opens with "Generated by
`scripts/generate-records-index.mjs` — do not edit by hand." That is still accurate about the
*editing*.

- **Coverage — fixed.** The generator enumerates `docs/records/` as an input since
  `e3e5fcf54`; before that it wrote into the directory without ever reading it, so every
  record filed beside the index was missing from the one page that calls itself the entry
  point — six of them, not one (`git show --numstat e3e5fcf54` prints `docs/records/README.md`
  +16/−1; the file is 124 lines at `e3e5fcf54^` and 139 at `e3e5fcf54`). Prefer the line the
  tool prints about itself to arithmetic that ages: `ok: docs/records/README.md matches the
  generator (46 ADRs, 4 research, 17 phased, 0 audits, 14 scattered, 2 observability,
  6 records)`; the six record rows are `docs/records/README.md:97`–`:102`. The older finding
  stands as the reason this matters: verified 08-09-26 that a hand-run refresh added
  **ADR #43 (cloud sync), #45, #46 and #47**, four decisions merged without appearing in the
  registry.
- **Freshness tooling — exists.** `node scripts/generate-records-index.mjs --check`, added
  by `d711fad4d`, renders twice, refuses to assert if the two renders differ, compares the
  result against the committed file, exits 1 naming each differing line on drift and 0 with
  one `ok:` line when fresh, and writes nothing either way. The sentence this bullet replaces
  read, in full: "The script has no `--check`/`--dry-run` mode, so a CI freshness gate needs
  one added first (run it to a temp copy and diff) — that is a code change and has not been
  made." True when written, and afterwards an instruction to write code that already exists.
- **Freshness enforcement — absent, by decision.** `git grep -n generate-records-index
  -- .githooks .github scripts/check.sh` returns nothing (exit 1): no hook step, no CI job, no
  local gate runs the refresh or the check, so the index is fresh only because someone typed
  the command. The wire is deliberately not pulled yet — two records are dirty in other
  sessions' working trees at the moment of writing (`git status --porcelain -- docs/records`
  lists `JOURNAL.md` and `audit-open-findings.md` as ` M`), and a freshness gate that fires on
  content someone is mid-way through writing is an event that cries wolf.
  It lands in the same change as the first record that trips it, in a quiet tree.

Refresh with `node scripts/generate-records-index.mjs` after adding or amending a record.
Two things the generator faithfully reproduces rather than fixes: the duplicate `#43`
emits two rows, and the audits section stays empty because the script scans a root `audit/`
directory that `0689d5652` deleted in the same commit that wrote the script — an inert
branch, kept on purpose and recorded as such in the script rather than quietly removed.
- **Status vocabulary:** `Proposed / Accepted / Implemented / Partially Implemented / Superseded / Archived`
